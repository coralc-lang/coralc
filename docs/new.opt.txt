Static Spatial Layout Sorting of Stack Variables (Anti-Clustering)

    What it does: Most compilers allocate local stack variables in the order they are declared or encountered. This optimization reorganizes and re-sorts local variables on the stack frame entirely based on access frequency and size class, grouping hot variables together to fit within a single 64-byte cache line, while pushing cold variables (like large error buffers or infrequent flags) to separate lines.

    Why it's non-mainstream: Compilers usually leave stack layout to simple linear allocation or basic alignment rules. Doing a static data-flow analysis of access frequency to layout local stack frames directly improves L1 data cache hit rates across generic architectures without requiring profiling passes.

Return Value Optimization (RVO) Propagation / Aggressive SROA: Scalar Replacement of Aggregates (sroa) takes structures/tuples allocated on the stack and breaks them down into individual scalar variables so they can live purely in registers.

Control-Flow Tail Duplication: Duplicating the tail of a basic block into its incoming jump targets to eliminate unconditional branches and expose further constant folding or selection patterns across basic block boundaries.

Instruction Density / Code Size Packing (Macro-Fusion Prep): Rearranging independent micro-operations into tight sequence pairs that are known to pair well in decoders across standard architectures (like matching a compare/test instruction directly adjacent to a conditional branch) to make hardware macro-fusion easier for generic x86 and ARM decoders.

Idempotent Op Removal / Redundant Write Suppression: Detecting consecutive, identical store operations to the same memory location or register where no intervening read or side effect occurs, stripping out the redundant write entirely.

Redundant Branch Inversion Flattening

    What it does: When code contains sequential conditional checks that evaluate overlapping or inverse predicates (e.g., checking if (x > 5) in one block and later if (x <= 5) without modifying x), this optimization tracks the path constraints through the CFG and replaces the second branch with an unconditional jump or direct register state propagation.

    Why it's non-mainstream: While basic branch folding handles immediate if/else blocks, deep path-sensitive inversion tracking across complex, separated basic blocks is usually bypassed by mainstream compilers unless heavy global value range propagation (VRP) is running, making it a lighter-weight alternative to capture logic redundancies.

Jump-to-Jump (Branch Chain) Flattening

    What it does: Scans basic block terminators for unconditional branches that point directly to another unconditional branch (e.g., block A jumps to block B, and block B's only content is an unconditional jump to block C). The pass rewrites block A's target directly to C.

    Why it's useful: It streamlines control flow graphs without altering execution semantics, making basic blocks tighter and reducing the number of taken jumps the processor's branch predictor has to track.

Commutative Operand Canonicalization Pass
What it does: For commutative operations (like addition, multiplication, bitwise AND/OR/XOR), this pass enforces a strict, deterministic ordering on the operands (e.g., sorting them by value ID, register name, or constant status so that smaller IDs or constants always appear on the left).
Why it's useful: It has zero side effects and doesn't change semantics, but it radically increases the hit rate of subsequent Common Subexpression Elimination (CSE) and Global Value Numbering (GVN) passes by ensuring x + y and y + x look identical to the compiler.

Involution Chain Collapse (Self-Inverse Elimination)
What it does: Identifies adjacent or chained pairs of operations that are exact inverses of each other (involutions) and strips them both out entirely. Examples include:Bitwise NOT twice: $\text{NOT}(\text{NOT}(x)) \rightarrow x$Negation twice: $-(-x) \rightarrow x$Bitwise XOR with the same constant twice: $(x \oplus C) \oplus C \rightarrow x$Why it's useful: Frontends or macro expansion often generate redundant wrapping and unwrapping layers. This pass cleanly flattens them out with absolute semantic safety.

Redundant Type Cast and Extension Elimination
What it does: Analyzes value ranges or source types to eliminate nested, redundant casting operations. For instance, if a 32-bit integer is zero-extended to 64-bits, and then immediately truncated or extended again without any intervening arithmetic that alters the upper bits, the intermediate casting instructions are stripped.Why it's useful: It lightens the load on the instruction selector by removing useless widening/narrowing instructions that compilers often have to emit as explicit machine code movements.

Lexicographical Canonicalization of Commutative Trees

    What it does: Flattens deeply nested, associative, and commutative expression chains (like additions or bitwise operations, e.g., (c + (a + b))) and deterministically sorts the operand nodes using a strict lexicographical ID or weight order.

    Why it's side-effect-free & useful: Frontends and early passes often generate equivalent mathematical expressions in completely different syntactic orders. By enforcing a rigid sorting rule, this pass ensures that structurally identical expressions match identically, dramatically boosting the hit rates of your existing cse.crl and gvn.crl passes without altering program semantics.

Global Redundant Type-Cast Striping

    What it does: Scans the IR for chains of conversion operations (such as i32 -> i64 -> i32 or truncation followed immediately by zero-extension) where the intermediate type conversion is proven redundant because the value's range never exceeded the narrower bounds.

    Why it's side-effect-free & useful: Generic frontends frequently emit redundant widening and narrowing casts to satisfy strict typing rules. While local peephole cleaners catch basic patterns, a dedicated structural pass tracking range preservation across basic block boundaries strips out unnecessary conversion instructions entirely.

Static Branch-Condition Factoring (Guard Extraction)

    What it does: Identifies adjacent or nested basic blocks that evaluate overlapping boolean sub-expressions (e.g., checking if (x > 5) in one branch and later if (x > 5 && y < 10)), and factors out the dominant invariant checks into a single leading block.

    Why it's side-effect-free & useful: This is a purely logical transformation of the Control Flow Graph (CFG) that reduces redundant comparisons. It relies entirely on boolean algebra and path constraints, ensuring zero side effects while simplifying jump targets before code generation.
