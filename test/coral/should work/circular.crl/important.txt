you know how in c++ you have to forward declare a symbol (like a function before you use it) or... are forced to move its definition to before its usage?

a multi-pass based compiler solves this by using multiple passes to collect and register symbols before evaluating symbols. this is fine for most languages. until you hit cyclic imports.

file A needs symbol B from File C. and File C needs symbol D from File A.

now both files need to import the other. a pass based compiler breaks here.

so the solution is...

firstly collect all known symbols, then when evaluating any symbol for instance 

let x = y;

if y has been evaluated already, the good to go. if not mark that

"x depends on y"

so whenever y get evaluated your compiler will then fire up to evaluate x.

back to our cyclic import problem.

File A needs symbol B from File C.

but File C hasn't been loaded yet, so A registers a dependency on Symbol B that it needs. when File C eventually gets loaded, it will check all symbols that were waiting for it and resume their evaluation. 

File C needs symbol D from File A.

at this point File has been loaded so this one is straight forward.

at the end of the day if you still have any waiting symbols, you can report cyclic errors. like

let a = b;
let b = a;

they both depend on each other.
